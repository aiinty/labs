# Лабораторная работа № 12

## Подключение к веб-сервису: чтение и разбор ответа

### О чём лабораторная?

До этого момента лента объявлений в приложении работала данными, которые мы создали прямо в коде. Теперь подключим приложение к веб-сервису: получим объявления через HTTP API, разберём JSON-ответ и покажем данные в существующем `RecyclerView`.

#### Шаг 3. Изучите структуру ответа

Сервер возвращает не просто массив объявлений, а объект с двумя полями: `items` и `meta`.

Пример структуры ответа:

```json
{
  "items": [
    {
      "id": 10,
      "title": "Гитара",
      "description": "Акустическая гитара",
      "price": 7000,
      "deal_type": "sale",
      "photo_url": null,
      "category": {
        "id": 2,
        "name": "Музыка",
        "emoji": "🎸"
      },
      "author": {
        "id": "UUID-ПОЛЬЗОВАТЕЛЯ",
        "username": "student",
        "about_me": null
      }
    }
  ],
  "meta": {
    "total": 1,
    "page": 1,
    "page_size": 20,
    "total_pages": 1
  }
}
```

Это пример структуры, обратите внимание:

- `items` - массив объявлений
- `meta` - информация о пагинации
- `category` - вложенный объект категории
- `author` - вложенный объект автора
- `photo_url` и `about_me` могут иметь значение `null`
- `deal_type` принимает одно из значений `sale`, `free` или `exchange`

### Часть 3. Создаём модели для ответа сервера

На этом этапе мы ещё не отправляем запрос. Сначала описываем данные, которые приложение ожидает получить.

Для ответа API создадим отдельные классы. Это позволит не менять существующую модель `Item` и адаптер раньше времени. В проекте создайте пакет `dto` для моделей ответа API.

#### Шаг 5. Создайте `PaginatedResponse.java`

Этот класс будет универсальным: параметр типа `T` позволяет использовать его для страниц с объектами разных типов.

```java
public class PaginatedResponse<T> {

    private List<T> items;
    private MetaResponse meta;

    public List<T> getItems() {
        return items;
    }

    public MetaResponse getMeta() {
        return meta;
    }
}
```

Класс содержит список объектов `items` типа `T` и метаданные пагинации `meta`.

### Часть 4. Подключаем Retrofit

Retrofit позволяет описывать HTTP-запросы в виде Java-интерфейсов, а Gson преобразует JSON-ответ в созданные нами модели.

#### Шаг 1. Добавьте зависимости

Откройте файл `build.gradle.kts (Module :app)`.

Внутри блока `dependencies` добавьте:

```kotlin
implementation("com.squareup.retrofit2:retrofit:2.12.0")
implementation("com.squareup.retrofit2:converter-gson:2.12.0")
implementation("com.squareup.okhttp3:logging-interceptor:3.14.9")
```

Нажмите `Sync Now` и дождитесь завершения синхронизации Gradle.

#### Шаг 2. Разрешите сетевые запросы

Откройте `AndroidManifest.xml` и добавьте разрешение перед тегом `<application>`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

Наш сервер использует адрес с `http://`, потому нужно добавить в существующий тег `<application>`:

```xml
android:usesCleartextTraffic="true"
```

#### Шаг 3. Создайте `RetrofitClient.java`

В пакете `network` создайте класс-клиент:

```java
public class RetrofitClient {

    private static final String BASE_URL = "http://95.31.156.238:8000/";

    private static Retrofit retrofit;

    public static Retrofit getRetrofit() {
        if (retrofit == null) {
            HttpLoggingInterceptor logging =
                    new HttpLoggingInterceptor();

            logging.setLevel(
                    HttpLoggingInterceptor.Level.BODY
            );

            OkHttpClient client = new OkHttpClient.Builder()
                    .addInterceptor(logging)
                    .build();

            retrofit = new Retrofit.Builder()
                    .baseUrl(BASE_URL)
                    .client(client)
                    .addConverterFactory(
                            GsonConverterFactory.create()
                    )
                    .build();
        }

        return retrofit;
    }

    public static ApiService getApiService() {
        return getRetrofit().create(ApiService.class);
    }
}
```

### Часть 5. Описываем запрос в API-интерфейсе

Теперь, когда мы знаем структуру ответа и создали соответствующие модели, можно описать запрос.

#### Шаг 1. Создайте `ApiService.java`

```java
public interface ApiService {

    @GET("items")
    Call<PaginatedResponse<ItemResponse>> getItems(
        @Query("page") int page,
        @Query("page_size") int pageSize,
        @Query("category_id") Integer categoryId
    );
}
```

Разберём код:

- `@GET("items")` - отправить GET-запрос по пути `/items`
- `@Query("page")` - передать номер страницы
- `@Query("page_size")` - задать размер страницы
- `@Query("category_id")` - передать необязательный фильтр
- `Call<PaginatedResponse<ItemResponse>>` - получить ответ, который преобразуется в объект `PaginatedResponse<ItemResponse>`

### Часть 6. Выполняем запрос и обрабатываем ответ

#### Шаг 1. Выполните запрос асинхронно

Сетевой запрос нельзя выполнять в главном потоке интерфейса, потому используем `enqueue()`:

```java
ApiService apiService = RetrofitClient.getApiService();

apiService.getItems(1, 20, null).enqueue(new Callback<PaginatedResponse<ItemResponse>>() {

    @Override
    public void onResponse(
        Call<PaginatedResponse<ItemResponse>> call,
        Response<PaginatedResponse<ItemResponse>> response
    ) {
        if (response.isSuccessful() && response.body() != null) {

            PaginatedResponse<ItemResponse> result = response.body();
            List<ItemResponse> items = result.getItems();
            MetaResponse meta = result.getMeta();

            // здесь можно обработать полученный  список

        } else {
            // попали сюда так как сервер вернул HTTP-ошибку или отсутствует тело ответа
        }
    }

    @Override
    public void onFailure(
        Call<PaginatedResponse<ItemResponse>> call,
        Throwable t
    ) {
        // ошибка соединения или выполнения запроса
    }
});
```

#### Шаг 2. Преобразуем ответ API в модель приложения

В проекте уже есть класс `Item`, который используется локальными объявлениями и адаптером `ItemAdapter`.

`ItemResponse` описывает ответ **сервера**, а `Item` - данные, которые использует **приложение**. Эти классы **не обязаны совпадать**: например, сервер возвращает вложенные объекты `category` и `author`, а модель приложения может хранить название владельца и числовой идентификатор категории.

Создайте отдельный метод преобразования внутри класса `ItemResponse`. Например, логика преобразования может выглядеть так:

```java
private static Item mapToItem(ItemResponse response) {
    int categoryId = response.getCategory() != null
            ? response.getCategory().getId()
            : -1;

    String owner = response.getAuthor() != null
            ? response.getAuthor().getUsername()
            : "Неизвестный автор";

    String imageUri = response.getPhotoUrl();

    DealType dealType = DealType.SALE;

    if ("free".equals(response.getDealType())) {
        dealType = DealType.FREE;
    } else if ("exchange".equals(response.getDealType())) {
        dealType = DealType.EXCHANGE;
    }

    return new Item(
        response.getId(),
        dealType,
        categoryId,
        response.getTitle(),
        response.getPrice(),
        response.getDescription(),
        owner,
        imageUri
    );
}
```
